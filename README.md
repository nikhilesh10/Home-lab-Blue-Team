# Home Lab --- Blue Team / SOC

A hands-on cybersecurity home lab focused on **SOC operations, blue-team
detection, SIEM analysis, incident investigation, and security
monitoring**.

This repository documents attacks performed in a controlled virtual lab,
the telemetry generated by those attacks, the detections built in
Splunk, and the investigation process used to understand what happened.

> **Lab only:** All attack activity documented here is performed against
> intentionally controlled virtual machines owned and operated for
> learning purposes.

------------------------------------------------------------------------

## 🎯 Objectives

The goal of this project is to build practical experience with:

-   Security Operations Center (SOC) workflows
-   SIEM monitoring and investigation
-   Log collection and analysis
-   Windows security telemetry
-   Linux authentication and system logs
-   Network security monitoring
-   Attack detection and correlation
-   Splunk Search Processing Language (SPL)
-   MITRE ATT&CK mapping
-   Incident investigation and reporting
-   Detection engineering
-   Blue-team tooling and workflows

The emphasis is on **actually generating the activity, collecting the
evidence, detecting it, and documenting the investigation** rather than
only completing theoretical exercises.

network for communication between the attack, target, and SIEM systems.

### 1. SSH Brute Force / Password Guessing

**Status:** ✅ Completed

A controlled SSH password-guessing simulation was performed against the
Windows target.

The investigation covered:

-   Windows Event ID `4625` --- failed logon
-   Windows Event ID `4624` --- successful logon
-   Windows Event ID `4688` --- process creation
-   OpenSSH telemetry
-   Splunk field extraction
-   Failed authentication threshold detection
-   Successful-login correlation
-   Logon ID correlation
-   Process-chain analysis
-   MITRE ATT&CK mapping

Observed process chain during the controlled successful SSH session:

``` text
sshd.exe
   ↓
conhost.exe
   ↓
cmd.exe
   ↓
whoami.exe
```

MITRE ATT&CK techniques documented:

-   **T1110.001 --- Password Guessing**
-   **T1021.004 --- SSH**

The activity was intentionally generated as part of the lab and was
assessed as an **authorized lab simulation**, not a real compromise.

## 🧠 Investigation Methodology

Each investigation follows a repeatable SOC workflow:

### 1. Generate the activity

Perform a controlled attack or simulation against a lab target.

### 2. Identify telemetry

Determine which logs, events, processes, or network traffic the activity
generates.

### 3. Ingest the telemetry

Forward relevant logs into Splunk.

### 4. Build the detection

Write SPL queries that identify the suspicious behavior.

### 5. Investigate

Correlate:

-   timestamps
-   accounts
-   source information
-   processes
-   event IDs
-   logon IDs
-   network information
-   related activity

### 6. Map the behavior

Where appropriate, map observed behavior to MITRE ATT&CK.

### 7. Assess the incident

Determine whether the activity represents:

-   expected behavior
-   authorized testing
-   suspicious activity
-   or confirmed malicious behavior within the lab scenario

### 8. Document the findings

Record the evidence, queries, timeline, conclusions, and lessons
learned.

## ⚠️ Lab Safety

This project is designed as a controlled cybersecurity lab.

-   Attacks are performed only against lab-owned virtual machines.
-   No real-world targets are intentionally attacked.
-   Credentials and secrets are not stored in this repository.
-   VM disks, large PCAP files, and other unnecessary binary files are
    excluded from Git.
-   Sensitive information should be sanitized before publishing
    screenshots or logs.
